# 后处理规范：主题筛选 → 论文标签 → 简要解读 → 组装 → 飞书归档

从 zotero-arxiv-daily 的原始输出出发，由 AI Agent 产出「原始论文列表 + 含标签的主题筛选表 + 论文解读」的单一文档并归档到飞书知识库。平台无关流程；用哪个 Agent 跑都可以。

## 约束

- 论文原文用 Agent 自带的抓取/读文件工具取（`web_extract` / `web_fetch` / `read_file`）
- 后处理开始时必须读取 [paper-tags.yaml](paper-tags.yaml)，标签及其解释、单选/多选规则均以该文件为准。
- 对原始日报中的全部 N 篇论文逐篇判断并打标签，只有符合主题的 M 篇进入论文解读；N 指原始报告的论文数，不是当日 arXiv 的全部论文数。
- 五类标签只写在「主题筛选结果」表中。原始「每日 arxiv 推送」完整保留，后面的论文解读不再添加标签字段或标签列表。
- 飞书文档一次性上传完整内容：原始论文列表 + 含标签的主题筛选表 + 论文解读，一个文档、一次导入。

## 1. 主题筛选

匹配口径（结合标题、摘要、TLDR 与研究内容综合判断）：

| 级别 | 关键词 |
|------|--------|
| 核心 | 前馈重建（feed-forward / feedforward reconstruction）、占据预测（occupancy prediction / 3D occupancy / BEV occupancy / semantic occupancy）、环视（surround-view） |
| 相关 | 可泛化 3DGS、稀疏视图重建、高斯表示、驾驶场景重建、轻量化实时推理 |
| 不相关 | 纯图像匹配、通用分类/检测/分割（与重建/占据无关）、非驾驶场景的独立任务 |

只要与上述任一方向有实质性关联即可入选。

先为每篇论文记录入选或未入选及一句话理由，再进入标签步骤。领域标签用于归类，不能替代这一步的主题判断。

## 2. 论文标签

按 [paper-tags.yaml](paper-tags.yaml) 为**每篇论文**选择五类标签，在主题筛选表中增加「研究领域、输入配置、平台、场景、技术特征」五列，顺序固定：

- **研究领域**单选，沿用既定科研任务分类；前馈高斯、优化高斯分别指两类高斯重建任务，与 Occ 等任务并列，按论文主要研究的任务归类。
- **输入配置、平台、场景**按实际输入、采集或部署平台、实验环境选择，可多选；夜间、雨雪、大雾仅在论文专门研究相应条件下的算法时标注，数据集中出现这些样本不足以添加。
- **技术特征**可多选，也可没有适用标签。优先从 YAML 候选中选择，未覆盖但有原文依据的技术特征可简要补充。

YAML 中 `单目/双目/多目/环视` 等写法保留为一组候选，共用解释；输出时只选其中适用的标签，多个标签用 `、` 分隔。证据不足的字段写 `未说明`；已核实但没有适用技术标签时写 `—`。`其他（…）` 的名称长度等细则也见 YAML。

先依据标题、摘要和 TLDR 初判，需要确认输入、方法或实验设置时获取原文，优先 HTML。论文解读复用已取得的原文，信息不足时明确说明，不根据相关工作或潜在应用补标签。

完成标签后输出下表，**全部 N 篇各占一行，沿用原始日报顺序与编号**。在「相关性判断」中写 `入选：理由` 或 `未入选：理由`，入选共 M 篇；未入选原因也放在本列，避免另列一份重复清单。

```markdown
## 主题筛选结果

> 主题口径：前馈重建 / 占据预测。今日共 N 篇论文，M 篇符合主题。

| # | 论文 | arXiv | 研究领域 | 输入配置 | 平台 | 场景 | 技术特征 | 相关性判断 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | **论文标题** | [ID](链接) | 领域标签 | 输入标签 | 平台标签 | 场景标签 | 技术标签或 — | 入选：一句话理由 |
| 2 | **论文标题** | [ID](链接) | 领域标签 | 输入标签 | 平台标签 | 场景标签 | 技术标签或 — | 未入选：一句话理由 |
```

即使 M = 0，也保留全部 N 篇的标签与判断，并在解读部分说明本日没有符合主题的论文。

## 3. 论文解读

对每篇入选论文通过 arXiv 链接取原文（优先 HTML 版 `arxiv.org/html/XXXX`）。7 个维度，**每篇 ≤500 字**：

1. **任务定义** — 要解决什么问题
2. **一句话总结** — 核心方法
3. **问题与创新** — 现有方法不足 & 本文创新点
4. **架构概述** — 系统流程（分步）
5. **核心模块** — 关键技术实现细节
6. **实验概述** — 训练数据、评测基准、对比方法、核心结果
7. **批判性思考** — 亮点、局限、对课题（环视前馈高斯重建/占据预测）的启发

优先级规则：

- ≤5 篇入选 → 全部按 7 维格式解读。
- \>5 篇 → 优先选 Top 5 按 7 维格式解读，其余列标题 + 链接 + 一句话摘要。
- 与「环视 + 前馈 + 占据」直接撞车的标 ⭐ **必须精读**，优先纳入 Top 5；若此类论文超过 5 篇，则全部精读。

本节只写论文内容与研究启发，不重复主题筛选表中的五类标签。

产出格式：

```markdown
## 论文解读

### 1. 论文标题 ⭐
**链接：** https://arxiv.org/abs/XXXX
**机构：** 第一单位

**任务定义：** …
**一句话总结：** …
**问题与创新：** …
**架构概述：** …
**核心模块：** …
**实验概述：** …
**批判性思考：** …
```

## 4. 组装

原始输出与后处理结果合并成**一个** Markdown（块间留 `---` 分隔线），参考 [汇总文档模板](../templates/daily-push-report.md)。原始输出保持完整，标签只在追加的主题筛选表中出现：

```bash
DATE=$(date +%F)
RAW_FILE="${ARXIV_DAILY_PROJECT:-$HOME/Libraries/zotero-arxiv-daily}/outputs/daily-arxiv-${DATE}.md"
INTERP="/tmp/daily-interpretation-${DATE}.md"   # 步骤 1-3 的产出：含标签的筛选表 + 解读，开头带 `---`
COMBINED="/tmp/daily-push-${DATE}.md"

cat "$RAW_FILE" "$INTERP" > "$COMBINED"
wc -l < "$COMBINED"
```

最终文档结构：

```text
# Zotero arXiv Daily - YYYY-MM-DD
（原始 N 篇论文 TLDR）
---
## 主题筛选结果
（N 行论文；五个标签列；每行含入选或未入选理由）
## 论文解读
（仅符合主题的论文，按精读与简述规则输出，不附加标签）
```

## 5. 飞书归档（feishu-cli）

```bash
DATE=$(date +%F)
SPACE_ID=7621015102212295908
PARENT_NODE=D67vwKFYyiZr0gk080dcr89tnyb     # 文献阅读 → 每日推送（C54KwvndwibrEqkf2zvcHSCfnte 是它的父目录）

# A. 导入合并文档
feishu-cli doc import "/tmp/daily-push-${DATE}.md" --title "每日文献推送 ${DATE}" --output json
# → 记下 document_id

# B. 移到每日推送节点
feishu-cli wiki move-docs <document_id> --space-id "$SPACE_ID" \
  --parent-node "$PARENT_NODE" --obj-type docx --output json

# C. 取链接
feishu-cli doc get <document_id> --output json
```

**回读校验**（逐项确认）：

```bash
feishu-cli doc export <document_id> --output /tmp/verify-${DATE}.md
grep -c "批判性思考" /tmp/verify-${DATE}.md      # 应 = 实际采用 7 维格式解读的篇数
feishu-cli wiki nodes "$SPACE_ID" --parent "$PARENT_NODE" --output json | grep "$DATE"
```

导出后检查实际内容，不能只凭导入成功或表格行数判定完成：

- 原始 N 篇论文及其 TLDR 完整保留。
- 「主题筛选结果」表有 N 行论文、五个标签列，每篇恰好出现一次；入选行数为 M。
- 研究领域单选，多选标签按 `、` 分隔；组内候选、其他的格式和补充技术标签符合 YAML 规则，未把整个 `/` 分组当成一个标签。
- 原始输出与论文解读没有新增的标签字段或标签列表；五类标签集中在筛选表。
- M 篇入选论文均有解读或简述，⭐ 论文均采用 7 维格式；`批判性思考` 的数量等于实际 7 维解读篇数，不一定等于 M。
- 文档位于「文献阅读 → 每日推送」的当日节点，正文中的论文链接和标签表可读。

move 可能提交异步任务，等 3-5s 再验证；出现重复节点用 `echo y | feishu-cli wiki delete <node_token>` 删旧的。

**补充已有文档**（原文档只传了原始输出时）：

```bash
feishu-cli doc content-update <doc_token> --mode append --markdown-file /tmp/feishu-append-${DATE}.md
```

doc_token 查询：`feishu-cli wiki nodes "$SPACE_ID" --parent "$PARENT_NODE" --output json`。

## 6. 汇报文本

```text
📚 每日文献推送
📅 YYYY-MM-DD
📊 总论文数：N 篇 | 符合主题：M 篇
📎 飞书文档：每日文献推送 YYYY-MM-DD（附链接）

（如有特别值得关注的论文，1-2 句点出）
```

无新论文时：

```text
📚 每日文献推送
📅 YYYY-MM-DD
今日没有新论文。
```

（怎么把这段文本送达用户由各平台自己的投递机制决定，见平台侧配置。）

# 任务提交流程

本流程只负责把已准备好的实验提交上云，不把本地验收、Git 发布、云端运行和结果分析混成同一个完成条件。阅读前先遵循 SKILL.md 中的固定默认值与权限约束。

## 1. 确定本轮输入

从本轮方案、本地验收交付和项目文件提取已有信息，只询问真正缺失或冲突的内容：

- 项目简称、工作树简称、实验简称、任务名称、本轮输出根目录。
- 本地工作树、云端工作树绝对路径、预期分支、待运行的已推送 commit。
- 单一实验脚本及必要参数；它可以包含训练、评估或审计，不限定为 `mim train`。
- 云端需要的依赖、权重、长期缓存，以及这些输入的准备状态。
- 对本轮创建任务的授权；使用默认资源不代表自动获得提交授权。

正常命名：`dzp_<project>_<worktree>_<experiment>`，依次为姓名、项目、工作树、实验。例如 `svocc` 项目的 `dev_semantic` 工作树简写为 `sem`，实验 `carve_v2_fast` 对应 `dzp_svocc_sem_carve_v2_fast`；`dev_asy` 使用 `asy`。前三项各用一个简短字段，实验部分可以包含下划线。

- 总长度最多 31 个字符（包含下划线），`dzp_svocc_sem_gauss_suppress_v1` 恰好达到上限。
- 绝不使用 `smoke`（不区分大小写），不添加日期后缀；环境验证任务可使用 `dzp_svocc_sem_env_check`。
- 工作树用已有简称，不把 `dev_semantic` 等完整分支名塞进名称。实验部分简洁而全面，保留核心方法、用途及必要版本；超长时作有意义的缩写，不靠直接截断或删除工作树字段凑长度。
- 名称不再强制等于输出目录末级名称。若目录包含冗长前缀、日期或其他内部信息，用 `--experiment` 指明实验简称，并在本地提交记录中保留名称与真实输出路径的对应。不得为满足命名改动实际输出目录或恢复路径。
- 多阶段脚本使用总输出根目录，不取内部的 `train` 等目录；从脚本读取真实默认值，不根据任务简称猜目录。未指定 `--experiment` 时，校验器从目录末级取名，并去除已有的一次工作树前缀（如 `sem_`），避免重复成 `sem_sem_`。

### 工作树不能硬编码

历史任务的云端目录包括：

| 场景 | 历史使用的云端目录 |
| --- | --- |
| SV-Occ 主工作树 | `/vepfs-mlp2/c20250502/haoce/dzp/SV-Occ` |
| Semantic 工作树 | `/vepfs-mlp2/c20250502/haoce/dzp/SV-Occ-sem` |
| ASY 工作树 | `/vepfs-mlp2/c20250502/haoce/dzp/SV-Occ-asy` |

这些是定位线索，不证明当前分支。根据本轮要求选择并核验工作树，不自动 checkout、reset、stash，不修改其他运行中任务使用的仓库。新项目的目录和环境脚本按其实际情况确定，不能直接套 SV-Occ 路径。

## 2. 固定五行入口

用户明确要求以下结构，不再压缩为两行，也不展开成冗长的初始化命令。以 Semantic 任务为例：

```bash
cd /vepfs-mlp2/c20250502/haoce/dzp/SV-Occ-sem
. /root/miniconda3/bin/activate
source haoce_activate.sh
bash cloud_sync.sh dev_semantic
PYTHONPATH=. MODE=cloud bash scripts/semantic_carve_v2_fast.sh
```

五行分别是：

1. `cd` 到本轮云端工作树，不固定为 SV-Occ 主目录。
2. `. /root/miniconda3/bin/activate`：火山平台任务固定的 conda 激活步骤。
3. `source haoce_activate.sh`：加载项目环境；沿用现有脚本，不把内容展开进入口。
4. 运行项目内的 Git 同步脚本，传入本轮预期分支。
5. **原样使用 Goal / 本地验收交付的单一实验指令**，不拆开其内部训练和审计，不另造一套启动参数。

按已有任务的格式，各行只用普通换行分隔，不加 `&&`，也不额外堆叠控制语句。脚本应如实返回错误；普通换行本身不保证前一步失败后停止后续命令，不能把脚本子进程退出描述成必然终止外层入口。

### 第四行的 Git 同步脚本

`cloud_sync.sh` 是 **SV-Occ 项目专用脚本**，放在 SV-Occ 仓库根目录，与 `haoce_activate.sh` 并列，由 SV-Occ 自己维护和测试；不放在 `scripts/` 下，也不作为本技能的通用模板。SV-Occ 的各工作树使用各自版本中的该脚本，其他项目使用自身的同步实现。

SV-Occ 的 `cloud_sync.sh` 负责：

- 核验当前位于仓库根目录、当前分支与参数一致；不自动切分支、reset 或 stash。
- 检查已跟踪文件没有未提交改动，避免覆盖云端改动。
- 在脚本内部设置 GitHub SSH 443，再执行 `git pull --ff-only origin <预期分支>`。
- 核验本地 HEAD 与本次取得的分支 HEAD 一致，打印分支和实际 commit；失败时以非零状态退出并报告错误。

它只处理 Git，不重新激活环境，不启动实验，也不操作数据、缓存或输出目录。具体依赖、GPU 数量、数据/权重/缓存、断点恢复与输出路径校验仍由第五行的实验脚本承担。

**首次启用前必须把同步脚本部署到云端工作树。** 脚本随 SV-Occ 项目代码发布，不由技能安装过程部署；只在本地提交或推送脚本，还不能让尚无该脚本的第四行自动拉取它自己。将首次部署作为上云准备事项，在有相应授权时通过已有代码同步方式完成；未部署则报告准备未完成，不能盲目提交。不要为解决首次部署擅自加长入口或创建额外云端任务。

每次启动都会同步分支，保留用户“任务重试时拉取最新修复代码”的习惯；实际 commit 留在日志中。版本变化后是否能复用旧进度，由项目兼容性校验决定。只有用户选择固定版本复现时，才另行设计固定 SHA 的运行方式。

不把多个命令压成一条超长字符串，不用内联 Python、heredoc 或编码文本绕过入口简洁要求。日志可以详细，入口保持上述五行。

## 3. 生成 YAML 与本地预检

从 [固定模板](ml-task-template.yaml) 创建本轮配置，默认只改 `TaskName`、`Entrypoint`：

- 队列名称和 ID 必须匹配。`ResourceQueueName` 优先于 ID，不能残留另一个队列名。
- 优先级 9、闲时资源、单机 4 卡 A100、镜像、读写挂载、鉴权和重试策略遵循 SKILL.md。若平台拒绝某项，报告原因，不自行换队列、降优先级、减卡或更换鉴权。
- `Description: ""`、`Tags: []` 必须保持，绝不填入 commit 或方案内容。
- 保留 `Preemptible: true`，不能因历史 YAML 导出遗漏而删除。
- TOS 和两处 vePFS 均显式 `ReadOnly: false`；这是挂载权限，不是覆盖已有数据的授权。
- 沿用现有 API 密钥配置。不提取截图中的密钥、不把 AK/SK 写进 YAML，也不猜测未验证的鉴权字段。如果 CLI 无法沿用现有鉴权，停止提交并报告，不切换身份或鉴权方式。
- 使用已经挂载的代码，两个代码上传路径留空。不上传数据/权重/work_dirs 的软链接目标。
- 依赖、缓存和输出目录检查先在本地落实为可执行脚本；无法在本地验证的云端事实明确列为待运行前校验，不伪称已验证。
- 检查本轮代码是否已按用户授权 commit/push，启动脚本是否包含在待运行版本中。提交权限不能代替 Git 发布权限。

离线校验命令（在技能目录执行）：

```bash
python3 scripts/validate_task_config.py /tmp/dzp_task.yaml \
  --project svocc --worktree sem --experiment carve_v2_fast \
  --work-dir work_dirs/sem_carve_v2_fast
```

校验器需要 PyYAML，仅检查配置，不联网、不执行入口、不创建任务。缺失工作树字段、名称超长、禁用词、日期后缀、模板占位值、重复 YAML 键、非空描述/标签、未获准的默认值变化都会失败。它不代替入口审查或用户授权，也不能验证 API 密钥在云端的权限。名称的语义是否简洁全面仍需人工审查。

只有用户明确要求某个差异时，才使用精确字段豁免，例如用户要求单卡后允许 `--allow-change 'TaskRoleSpecs[0].Flavor'`；必须同时调整实验脚本的进程数。不得把豁免作为绕过报错的手段；描述和标签不可豁免。不要修改基准模板来让一次性差异通过检查。

## 4. 授权前的简短摘要

展示实际入口，以及关键配置是否仍符合默认值。例如：

```text
任务：dzp_svocc_sem_carve_v2_fast
云端目录 / 分支：SV-Occ-sem / dev_semantic
输出根目录：work_dirs/sem_carve_v2_fast
代码：已推送的 commit；启动时按约定拉取分支，实际 SHA 写入日志
资源：c20250502，优先级 9，闲时资源，单机 4×A100-80G
存储 / 鉴权：默认三处读写挂载，沿用现有 API 密钥
重试：开启，120 秒，上限 10 次
描述 / 标签：空
默认值差异：无（如有，逐项写明用户授权）
入口：展示实际五行入口
将执行：volc ml_task submit -c /tmp/dzp_task.yaml --output json
```

默认值已确定时不反复询问用户选队列、镜像或卡数。用户已对同一份配置和本次提交明确授权时，可以继续；否则等待确认。不能把“帮我写提交指令”“改一下技能”当作提交许可。授权摘要必须对应最终 YAML；不能确认后又用 `--set`、`--priority`、`--entrypoint` 等参数悄悄覆写。

## 5. 一次提交与防止重复创建

1. 提交前只读检查同名、相同输出根目录是否已有活跃任务；如有，确认是否同一轮任务或平台重试，不能让两个写入者并行覆盖相同结果。历史完成任务不等于本轮可覆盖其输出。
2. 保留本轮 YAML 与本地提交记录；提交记录存放本地文件，不能填入平台描述/标签。记录包含任务 ID、实际配置、提交时间、提交前代码版本和授权的差异；运行时 SHA 以日志为准。
3. 经授权只执行一次：

   ```bash
   . "$HOME/.volc_env"
   volc ml_task submit -c /tmp/dzp_task.yaml --output json
   ```

4. 若请求超时或未收到任务 ID，先只读查询近期同名任务，并核对时间、入口等信息；找到已经创建的任务就使用其 ID。仍无法确定时报告，不盲目重新 submit。
5. 平台按已配置的 10 次上限自动重试；Agent 不因任务 Failed/Killed 就另建任务，更不能删除旧任务或停止平台重试中的任务。

## 6. 提交后一次回读，然后交回

- 拿到 ID 后查询一次，核对任务名、队列、规格、闲时资源、优先级及入口；需要时对照导出配置，注意导出字段可能有缺失。
- 此时若已经 Running，可读取最近 100 条日志，确认环境与实验入口启动；若仍 Queue/Staging，直接报告该状态，不等待、不轮询。
- 回报任务 ID、名称、当前状态及本地配置记录。区分“平台已接受”“已启动”“实验完成”，不能混用。
- 若回读发现配置不符，报告并请求方向，不自动取消、修改或重提。
- 除非用户另有持续监控要求，交回后由现有监控服务报告状态变化；结果下载与分析是后续阶段，不延长本地 Goal。
